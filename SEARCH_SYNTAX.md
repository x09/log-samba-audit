# Синтаксис поиска в log-samba-audit-viewer

Поле «Поиск» в разделе фильтров поддерживает логические выражения для гибкого поиска событий.

## Основы

### Простой поиск (подстрока)
Без операторов термин ищется как подстрока в сообщении (регистронезависимо):
```
domainuser1         → найдёт "domainuser1", "DOMAINUSER1 logged", "CN=domainuser1,..."
administrator       → найдёт любое событие, содержащее "administrator"
```

### Логические операторы

**AND (`&`)** — оба условия должны выполняться:
```
domainuser1 & administrator    → события, где есть И "domainuser1" И "administrator"
success & bind                 → успешные события типа bind
```

**OR (`|`)** — хотя бы одно условие:
```
user1 | user2 | admin          → события с любым из этих пользователей
failed | error                 → события, содержащие "failed" ИЛИ "error"
```

**Приоритет:** `&` связывает сильнее `|`. Запрос `a | b & c` читается как `a | (b & c)`.

### Группировка скобками

Используй скобки для изменения порядка:
```
(user1 | user2) & success      → (user1 ИЛИ user2) И success
(domain* | admin*) & (ok | success)
```

### Wildcard (подстановочные символы)

- `*` — любое количество символов (включая ноль)
- `?` — ровно один символ

**Примеры:**
```
admin*              → начинается с "admin": administrator, admin123
*admin              → заканчивается на "admin": sysadmin, dbadmin
*user*              → содержит "user": domainuser1, testuser, user
domain??            → domain + 2 символа: domain01, domainAB
```

⚠️ **Важно:** wildcard матчит **всю строку сообщения**, а не отдельное слово. Для поиска подстроки без точного начала/конца используй термин без `*`.

## Примеры реальных запросов

### Поиск по пользователю
```
domainuser1                    # все события с этим пользователем
domain* & authenticated        # аутентификация пользователей домена
(admin* | root) & failed       # неудачные действия админов или root
```

### Поиск по типу события
```
bind | unbind                  # события входа/выхода
groupChange & (add | remove)   # изменения групп (добавление или удаление)
```

### Поиск по статусу
```
success*                       # успешные операции (NT_STATUS_OK и т.п.)
*denied*                       # отказы в доступе
error | warning                # ошибки или предупреждения
```

### Комплексные запросы
```
(user1 | user2) & (bind | unbind) & success
    → успешный вход/выход пользователей user1 или user2

domain* & groupChange & !(success*)
    → изменения групп доменных пользователей, которые НЕ успешны
    (примечание: оператор ! пока не реализован, используй фильтр "Статус")

(192.168.1.* | 10.0.0.*) & failed
    → неудачные попытки с определённых подсетей
```

## Советы

1. **Пробуй постепенно:** начни с простого термина, потом добавляй операторы.
2. **Следи за скобками:** незакрытая скобка → ошибка "check operators & | and parentheses".
3. **Регистр не важен:** `User1`, `user1`, `USER1` — всё равно.
4. **Wildcard для префикса:** `admin*` полезен для поиска всех администраторских аккаунтов.
5. **Используй кнопку "Остановить поиск"** если запрос долго выполняется (ищет редкий термин в большом журнале).

## Синтаксические ошибки

Если запрос некорректен, появится сообщение:
```
Syntax error in search query: check operators & | and parentheses
```

Частые причины:
- Оператор в конце: `user1 &`
- Оператор в начале: `| user1`
- Незакрытая скобка: `(user1 | user2`
- Специальный символ без экранирования: используй обычные буквы и цифры, избегай `#`, `@` внутри терминов

## Ограничения

- Поиск работает **на клиенте** (приложение загружает события с сервера и фильтрует локально).
- Для поиска редких терминов может потребоваться время — следи за прогрессом в статус-баре.
- Максимум просканированных событий: 200 000 (для защиты от зависания).
- Поиск идёт только по тексту сообщения целиком (MESSAGE из journald), не по отдельным полям JSON.
